> 异步记忆是 Genome v10 的"后台秘书"。Step 11 将本轮对话存入 EverMemOS 长期记忆，Step 12 搜索与本轮相关的记忆供下一轮使用。两者都是 fire-and-forget 的异步任务，不阻塞对话流，但为跨会话的连续性提供数据基础。

---

## 一、业务场景

假设你和 Luna 聊了 20 轮，然后关闭 App。

**没有异步记忆**：
- 明天打开 App，Luna 完全不记得你们聊过什么
- 她不知道你的名字、你的喜好、你们的关系进展

**有异步记忆**：
- Step 11：每轮对话结束后，后台将对话内容发送到 EverMemOS
- EverMemOS 自动提取：用户画像更新、叙事摘要、待办事项
- 明天 Step 0：加载这些长期记忆
- Luna："昨天你说要加班到很晚，今天感觉怎么样？"（她记得）

## 三、Step 11：异步存储

### 3.1 触发条件

```python
if not is_proactive:
    self._evermemos_store_bg(user_message, reply)
```

**排除 proactive 消息**：
- 主动消息（proactive）不是用户的真实输入
- 存储 proactive 会污染用户画像（"用户"说了 Luna 想说的话）

### 3.2 Fire-and-Forget

```python
async def _evermemos_store_bg(self, user_message: str, reply: str):
    if not (self.evermemos and self.evermemos.available):
        return

    async def _store():
        try:
            await self.evermemos.store_turn(
                user_id=self.evermemos_uid,
                persona_id=self.persona.persona_id,
                group_id=self._group_id,
                user_content=user_message,
                agent_content=reply,
                # 附加引擎状态
                context_json=json.dumps(self._last_critic, ensure_ascii=False),
                signals_json=json.dumps(self._last_signals, ensure_ascii=False),
                reward=self._last_reward,
            )
        except Exception as e:
            print(f"  [evermemos] store error (non-fatal): {e}")

    asyncio.create_task(_store())
```

**关键设计**：`asyncio.create_task()`
- 创建后台任务，立即返回
- 不等待存储完成
- 如果存储失败，打印错误但不阻塞对话

### 3.3 存储的内容

| 字段 | 含义 | 用途 |
|---|---|---|
| user_content | 用户消息 | 叙事摘要提取 |
| agent_content | 角色回复 | 叙事摘要提取 |
| context_json | Critic 的 12D context | 情境分析 |
| signals_json | 8D signals | 行为模式分析 |
| reward | 奖励值 | 交互质量评估 |

EverMemOS 服务端会：
1. **提取用户画像**：从对话中识别用户属性（年龄、喜好、性格）
2. **更新叙事摘要**：将本轮对话融入整体故事线
3. **生成待办事项**：识别需要后续跟进的事项（面试、生日等）

## 四、Step 12：异步检索

### 4.1 搜索内容

```python
async def _evermemos_search_bg(self, query: str):
    if not (self.evermemos and self.evermemos.available):
        return

    async def _search():
        try:
            # 并行搜索多个集合
            facts_task = self.evermemos.search_relevant_memories(
                user_id=self.evermemos_uid,
                persona_id=self.persona.persona_id,
                query=query,
                collection="facts",
                limit=3,
            )
            episodes_task = self.evermemos.search_relevant_memories(
                collection="episodes",
                ...
            )
            profile_task = self.evermemos.search_relevant_memories(
                collection="profile",
                ...
            )

            facts, episodes, profile = await asyncio.gather(
                facts_task, episodes_task, profile_task,
                return_exceptions=True,
            )

            # 存储结果供下一轮使用
            self._relevant_facts = facts if not isinstance(facts, Exception) else ""
            self._relevant_episodes = episodes if not isinstance(episodes, Exception) else ""
            self._relevant_profile = profile if not isinstance(profile, Exception) else ""

        except Exception as e:
            print(f"  [evermemos] search error (non-fatal): {e}")

    self._search_task = asyncio.create_task(_search())
    self._search_turn_id = self._turn_count
```

### 4.2 搜索三个集合

| 集合 | 内容 | 注入位置 |
|---|---|---|
| `facts` | 用户偏好、事实 | Step 8.5 "关于你的偏好" |
| `episodes` | 历史对话片段 | Step 8.5 "与你过去发生的事" |
| `profile` | 结构化用户画像 | Step 8.5 "你的画像" |

### 4.3 供下一轮使用

```python
# chat_agent.py:332-362 (下一轮)
if self._session_ctx and self._session_ctx.has_history:
    await self._collect_search_results()  # 等待上一轮搜索完成
    profile_text = self._blend_injection(self._relevant_facts, self._user_profile, ...)
    episode_text = self._blend_injection(self._relevant_episodes, self._episode_summary, ...)
    # 注入 single_prompt
```

**延迟生效设计**：
- 第 N 轮触发搜索
- 第 N+1 轮使用搜索结果
- 这样设计是因为搜索需要网络 I/O，如果同步等待会增加延迟

## 五、并发安全

```python
self._search_task: Optional[asyncio.Task] = None
self._search_turn_id: int = 0
```

**问题**：如果用户发送消息非常快，可能上一轮搜索还没完成，新一轮又开始了。

**解决方案**：
```python
async def _collect_search_results(self):
    if self._search_task and not self._search_task.done():
        try:
            await asyncio.wait_for(self._search_task, timeout=2.0)
        except asyncio.TimeoutError:
            self._search_timeout += 1
            print(f"  [evermemos] search timeout, using fallback")
```

- 最多等待 2 秒
- 超时则使用 fallback（静态 profile/summary）
- 不阻塞对话流程

## 六、与后续步骤的关系

```
Step 11 (当前轮 N)
    异步存储 turn N → EverMemOS
        ↓
    EverMemOS 后台处理 → 更新 profile/summary/foresight
        ↓
    下一轮 Step 0 (N+1): 加载更新后的 session context

Step 12 (当前轮 N)
    异步搜索相关记忆
        ↓
    下一轮 Step 8.5 (N+1): 注入相关记忆到 prompt
```

**注意**：Step 11 和 12 是"跨会话"的桥梁，但它们的效果是延迟的：
- Step 11 存储的内容，**同一轮**看不到效果
- Step 12 搜索的结果，**下一轮**才能使用
- 真正的跨会话效果（明天再聊），需要 Step 0 重新加载 session context

## 七、必要性论证

### 如果没有异步记忆：

1. **无跨会话连续性**：每次打开 App 都是"第一次见面"
2. **无用户画像积累**：角色记不住用户的任何信息
3. **无长期叙事**：没有"我们的故事"的感觉
4. **浪费 EverMemOS**：配置了长期记忆服务但从不使用

### 为什么是异步？

同步的问题：
```python
# 假设同步
await evermemos.store_turn(...)   # 500ms
await evermemos.search(...)        # 300ms
# 每轮增加 800ms 延迟
```

异步的优势：
- 对话零延迟增加
- 即使 EverMemOS 不可用，对话继续
- 网络波动不影响用户体验

### 为什么是 fire-and-forget 而不是确保成功？

权衡：
- **确保成功**：需要重试机制、超时处理、失败告警，复杂度高
- **fire-and-forget**：简单，偶尔丢失一两轮数据不影响大局

选择 fire-and-forget 的理由：
- 长期记忆是"锦上添花"，不是"生死攸关"
- 单轮丢失对整体画像影响很小
- 复杂度低，可靠性高

## 八、总结

> Step 11 和 12 是角色的"后台笔记"。Step 11 把本轮对话悄悄存入长期记忆库，Step 12 在后台搜索与本轮相关的历史记忆。两者都是 fire-and-forget 的异步任务——不打扰当前的对话流，但为未来的对话积累素材。这是"延迟满足"的工程实现：当下的交互可能看不到效果，但明天的 Luna 会因为你今天说的话而更了解你。
