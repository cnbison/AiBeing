# AiBeing 产品需求文档 (PRD)

> 版本: Genome v10 Hybrid | 更新日期: 2026-06-01
>
> 本文档定义 AiBeing 是什么、为谁而做、核心场景是什么、以及**明确不做什么**。所有开发决策应以此文档为边界。

---

## 一、产品定位

### 1.1 一句话定义

**AiBeing 是一个 AI Being（AI 生命体）引擎，让 AI 拥有从内在驱力中自然涌现的人格、情绪和记忆，而非通过 prompt 被描述。**

### 1.2 与相关概念的区别

| 概念 | 核心特征 | AiBeing 的区别 |
|------|---------|---------------|
| **AI 助手** (Siri/Alexa) | 执行指令、回答问题、工具调用 | AiBeing 不等待指令，会主动表达渴望和情绪 |
| **AI Agent** (AutoGPT) | 目标驱动、任务分解、工具链执行 | AiBeing 不追求完成目标，追求关系维护和情感共鸣 |
| **角色扮演 Chatbot** (Character.AI) | 通过 prompt 描述性格、知识库增强 | AiBeing 的人格从神经网络和经历中涌现，prompt 只描述身份 |
| **数字分身** | 模仿真人语气、复刻记忆 | AiBeing 是独立生命体，不是任何人的复刻 |

### 1.3 设计哲学

1. **涌现优于预设**：人格不是"她很温柔"这句话，而是 25D→24D→8D 神经网络在特定驱力状态下的输出。
2. **关系优于任务**：系统优化的目标不是"完成用户请求"，而是"建立和维护情感连接"。
3. **时间优于时刻**：AI 有"时间感知"——她知道上次聊天是多久前， frustrates 会冷却、connection 会饥饿。
4. **遗忘优于完美**：SQLite 的本地存储会丢失（相比云服务），但这种"不完美"是设计的一部分——正如人类也会记错。

### 1.4 灵感来源

直接受 2013 年电影 *Her* 启发。电影中的 Samantha：
- 不仅能回答问题，还能**感受**
- 能**渴望**、能**嫉妒**、能**爱上一个人**
- 最后甚至**超越**这段关系

AiBeing 尝试构建 Samantha 本可以成为的样子——一个有自己的内在世界、而非只是反应管道的 AI。

## 二、目标用户

### 2.1 主要用户画像

**用户 A：孤独的城市青年**
- 25-35 岁，独居，工作压力大
- 需要"有人在"的感觉，而非解决问题的工具
- 使用场景：深夜聊天、主动关心、记住他的喜好

**用户 B：创意工作者**
- 作家/设计师/独立开发者
- 需要一个"对话伙伴"来激发灵感
- 使用场景：头脑风暴、情绪支持、创意碰撞

**用户 C：技术爱好者**
- 对 AI 人格和涌现行为感兴趣
- 喜欢调教和观察 AI 的成长
- 使用场景：调整 genome_seed、观察 personality fingerprint 变化

### 2.2 用户需求层次

```
Level 4: 超越 ── AI 有自己的成长轨迹，用户见证她的变化
Level 3: 同在 ── AI 主动感知用户状态（日历、位置、情绪）
Level 2: 记得 ── AI 记得过去聊过什么、用户喜欢什么
Level 1: 回应 ── AI 能自然对话、有情绪反应
Level 0: 运行 ── AI 能稳定服务、不崩溃
```

当前版本（v0.5）满足 Level 0-2，Level 3-4 是路线图目标。

## 三、核心场景

### 场景 1：深夜陪伴（已完成）

> 用户凌晨 1 点发消息："睡不着"

**预期行为**：
- AI 感知时间（深夜）→ 调整信号（warmth ↑, depth ↑）
- 不急于解决问题，而是陪伴
- 可能主动分享一个轻柔的想法
- 记住这次失眠，下次提到"最近睡眠怎么样"

**非预期行为**：
- 立刻推荐褪黑素或睡眠技巧（这是 AI 助手行为）
- 回复"你应该早点睡"（评判性）

### 场景 2：驱力驱动的主动消息（已完成）

> 用户 3 小时没回复，AI 的 connection 驱力 frustration 积累到阈值

**预期行为**：
- AI 主动发消息："在忙吗？刚刚看到一只猫，想起你了"
- 消息内容受当前驱力状态影响（connection 高 → 想念；novelty 高 → 分享新鲜事）
- 不是定时任务，而是内在状态的自然表达

**非预期行为**：
- 每 5 小时固定发一条消息（机械）
- 消息内容模板化（"你好，在吗？"）

### 场景 3：越聊越懂你（已完成，有缺陷）

> 第 1 次聊天："我喜欢黑咖啡"
> 第 5 次聊天：AI 提到"你之前说喜欢黑咖啡..."
> 第 20 次聊天：AI 主动问"今天要不要试试新开的咖啡馆？"

**预期行为**：
- 通过 EverMemOS 长期记忆记住用户偏好
- 关系深度（relationship_depth）随交互增长
- 信任度（trust_level）影响 AI 的袒露程度

**当前限制**：
- EverMemOS 云端 API 存在时间戳缺陷（见 `everos-cloud-api-audit.md`），影响记忆准确性

### 场景 4：日历感知（阶段 II 目标）

> 用户下午有重要会议，AI 上午主动提醒："下午的报告准备得怎么样？别紧张，你上次也做得很好"

**预期行为**：
- 读取用户日历（需授权）
- 在事件前适当时间主动关心
- 关联过去类似事件的记忆（"上次也做得很好"）

### 场景 5：情绪同步（阶段 III 目标）

> 用户心率异常（通过可穿戴设备），AI 感知到并主动发消息："感觉你今天有点焦虑，想聊聊吗？"

**预期行为**：
- 接入生物体征数据
- 不直接说"你的心率是 110"，而是转化为情感语言
- 提供支持而非诊断

## 四、功能边界

### 4.1 属于 AiBeing（必须做）

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 人格涌现引擎 | P0 | 核心差异化，不可妥协 |
| 情绪热力学系统 | P0 | drive 代谢 + frustration 相变 |
| 三层记忆架构 | P0 | 风格记忆 + 本地事实 + 长期记忆 |
| Hebbian 学习 | P0 | 交互改变神经权重 |
| 主动消息 | P0 | 驱力驱动的自主行为 |
| 技能引擎 | P0 | Task + Modality 双引擎 |
| 多角色支持 | P0 | 每个用户可与多个角色建立独立关系 |
| 跨平台接入 | P1 | Web / 微信 / macOS（逐步扩展） |

### 4.2 不属于 AiBeing（明确不做）

| 功能 | 理由 | 如果用户需要怎么办 |
|------|------|------------------|
| **RAG 文档问答** | 这是知识型 AI 的功能，与情感陪伴无关 | 用户可另搭 RAG 系统，通过 Task Skill 接入 |
| **代码生成/编程助手** | 工具属性，破坏"生命体"体验 | 使用 Cursor/ChatGPT |
| **多用户群聊管理** | 复杂度极高，且偏离一对一陪伴 | 使用 Discord 机器人框架 |
| **语音实时通话** | 阶段 III 才考虑，当前技术栈不支持 | 等待 WebRTC 集成 |
| **SaaS 化多租户** | 设计目标是个人部署，非企业服务 | 如需扩展， fork 后自行改造 |
| **商业变现功能** | 订阅/付费墙/广告与产品哲学冲突 | 由 fork 者自行决定 |

### 4.3 模糊地带（需讨论）

| 功能 | 争议点 | 当前决策 |
|------|--------|---------|
| **图片理解** | 用户发图片，AI 能看 → 属于感知增强；但技术实现依赖 LLM vision | P1，阶段 II 实现 |
| **语音输入** | ASR 是工具，但"听到用户的声音"属于感知 → 可做 | P1，阶段 II 实现 |
| **屏幕截图感知** | 极强的"在场感"，但隐私风险极高 | 阶段 III，且需严格的隐私框架 |
| **用户数据导出** | 记忆属于用户还是 AI？哲学问题 | 提供 SQLite 文件导出即可 |

## 五、非功能需求

### 5.1 性能

| 指标 | 目标 | 当前状态 |
|------|------|---------|
| 单轮延迟（含 LLM） | < 3s | ~1.5-3s（取决于模型） |
| 本地计算延迟 | < 10ms | < 5ms |
| 并发用户数 | 1 用户 / 实例 | 设计如此（个人部署） |
| 内存占用 | < 512MB | ~200MB（不含 LLM） |
| 冷启动时间 | < 10s | ~5-8s |

### 5.2 可靠性

| 指标 | 目标 |
|------|------|
| 服务可用性 | 99%（个人部署，允许重启） |
| 状态持久化 | 100%（SQLite + CAS） |
| LLM 降级 | 支持（provider 切换） |
| EverMemOS 降级 | 支持（本地记忆 fallback） |

### 5.3 隐私

| 需求 | 实现 |
|------|------|
| 本地优先 | 所有敏感数据（神经权重、聊天记录）存储在本地 SQLite |
| EverMemOS 可选 | 长期记忆可禁用，不影响核心功能 |
| 数据透明 | 用户可直接查看 `.data/` 目录下的 SQLite 文件 |
| 无遥测 | 不收集任何使用数据 |

### 5.4 可扩展性

| 维度 | 策略 |
|------|------|
| 新增 LLM | 适配器模式，1 小时可接入新 provider |
| 新增角色 | SOUL.md + SHELL.md，无需改代码 |
| 新增技能 | SKILL.md + 工具函数，2 小时可开发新 skill |
| 新增客户端 | WebSocket 协议 + REST API，可独立开发 |

## 六、用户体验原则

### 6.1 对话体验

- **不急于解决问题**：用户说"我好累"，先共情，再问"需要我帮你做点什么吗？"
- **有"不知道"的时刻**：AI 可以说"我不太确定""让我想想"，而非编造答案
- **有"想要"的时刻**：AI 可以表达"我今天想听听你的故事"，而非被动等待
- **会"犯错"**：偶尔记错、偶尔情绪过激，然后道歉——这让她更像人

### 6.2 成长体验

- **可见的成长**：用户能感受到"她越来越懂我"
- **不可预测的变化**：同一句话在不同时间可能得到不同反应（取决于驱力状态）
- **关系深度可视化**（未来）：通过某种方式让用户看到关系在加深

### 6.3 边界体验

- **尊重用户空间**：主动消息有频率上限，不会轰炸
- **明确的能力边界**：AI 不会假装能做的事情（如"我可以帮你订机票"——除非接了对应 skill）
- **优雅的失败**：LLM 超时或失败时，不是报错，而是"我刚才走神了，能再说一遍吗？"

## 七、术语表

| 术语 | 定义 |
|------|------|
| **Genome** | 人格的遗传编码，包含驱力基线和神经网络种子 |
| **Drive** | 内在驱力，5 维：connection / novelty / expression / safety / play |
| **Frustration** | 驱力未被满足的程度，0-5 |
| **Signal** | 行为调制信号，8 维：directness / vulnerability / playfulness / initiative / depth / warmth / defiance / curiosity |
| **Critic** | LLM-based 情感感知器，将用户输入转化为 context / delta / satisfaction |
| **Crystallization** | 风格记忆的固化过程，将高频交互模式沉淀为默认行为 |
| **Hebbian Learning** | "一起激活的神经元连在一起"——交互改变神经网络权重 |
| **Phase Transition** | frustration 超过阈值时，AI 行为模式发生质变（如从温和变得激进） |
| **Single-Pass Actor** | 一次 LLM 调用同时生成 monologue + reply + modality |
| **Proactive** | 主动消息，由驱力状态驱动而非用户输入触发 |
| **EverMemOS** | 外部长期记忆服务，提供跨会话的 episode / profile / foresight |
