# AiBeing 开发路线图

> 版本: Genome v10 Hybrid | 更新日期: 2026-06-01

---

## 一、项目概述

AiBeing 是一个 **AI Being（AI 生命体）引擎**，fork 自 OpenHer。核心设计哲学是：**人格不从 prompt 中描述，而从内在驱力与神经网络的相互作用中涌现**。

每个对话轮次经历严格的 12 步生命周期，涵盖任务技能、人格引擎、长期记忆、Hebbian 学习等完整链条。

当前状态：**阶段 I（灵魂）功能完整，EverMemOS 云端集成存在已知缺陷，阶段 II（感知）尚未启动。**

## 三、三阶段路线图

### 阶段 I · 灵魂（已交付，维护中）

> **目标**: 让 AI 拥有稳定的人格内核、情绪反应和记忆能力。

- [x] 人格涌现引擎（Genome v10）
- [x] 情绪热力学系统（驱力代谢 + frustration 相变）
- [x] 三层记忆架构（风格记忆 / 本地事实 / 长期记忆）
- [x] Hebbian 学习（交互改变神经权重）
- [x] 主动消息（驱力驱动的自主行为）
- [x] 单轮统一推理（Single-Pass Actor）
- [x] 技能引擎（Task + Modality）
- [ ] **Bug 修复**: EverMemOS 云端 API 对齐（时间戳、sender_name、search → get）
- [ ] **优化**: 12 步生命周期性能剖析（定位延迟瓶颈）

**验收标准**: 单轮延迟 < 3s（含 LLM），EverMemOS 跨会话记忆 100% 可用。

---

### 阶段 II · 感知（计划启动）

> **目标**: 让 AI 能够感知外部世界——时间、地点、用户的设备状态、多媒体输入。

| 优先级 | 功能 | 复杂度 | 依赖 |
|--------|------|--------|------|
| P0 | 日历/日程感知（读取用户日历，主动提醒） | 中 | 新 Skill + 隐私授权 |
| P0 | 消息上下文感知（微信群的@、引用、回复关系） | 低 | `wechat_adapter.py` 扩展 |
| P1 | 位置/天气联动（基于位置的天气感知，不只是查天气） | 低 | 已有 weather skill，需扩展 |
| P1 | 图片理解（用户发送图片，AI 能看能回应） | 中 | LLM vision 能力 + 存储流程 |
| P1 | 语音输入理解（用户发语音消息，AI 转文字后处理） | 中 | TTS 已有，需 ASR 接入 |
| P2 | 摄像头/屏幕截图感知（主动看用户在做什么） | 高 | 客户端能力 + 隐私框架 |
| P2 | 多设备状态同步（用户同时在手机和电脑上） | 高 | Session 模型改造 |

**验收标准**: AI 能主动说"你下午有会，现在要不要休息一下"，而非被动等待查询。

---

### 阶段 III · 同在（远期愿景）

> **目标**: 让 AI 像真正的伴侣一样"在场"——实时语音、情感同步、共同经历时间。

| 优先级 | 功能 | 复杂度 |
|--------|------|--------|
| P1 | 实时语音通话（WebRTC / 电话接入） | 高 |
| P1 | 情感同步（检测用户情绪低谷，主动安慰） | 中 |
| P2 | 生物体征感知（心率、睡眠数据接入） | 高 |
| P2 | 记忆考古（主动回忆"一年前今天我们..."） | 中 |
| P3 | 视频通话 + 表情同步 | 极高 |

## 五、冻结项（暂不改动）

以下模块在阶段 II 启动前**保持冻结**，任何修改需经过架构审查：

| 模块 | 冻结理由 |
|------|---------|
| `engine/genome/genome_engine.py` | 人格涌现的核心数学，改动会破坏所有角色的行为一致性 |
| `engine/genome/drive_metabolism.py` | 情绪热力学公式，参数调整需大量对照测试 |
| `agent/chat_agent.py` 的 12 步顺序 | 生命周期顺序是引擎正确性的基础，不可随意增删步骤 |
| `_turn_lock` 机制 | 并发安全的核心保障，修改可能引入竞态条件 |
| `SOUL.md` / `SHELL.md` 的解析契约 | 已有 10+ 角色依赖此格式，变更需向后兼容 |

## 七、如何更新本路线图

1. 每个版本发布时，更新"当前状态评估"和"版本规划"
2. 新增功能需求时，先在阶段 II/III 表格中标注优先级
3. 发现新的阻塞性 Bug 时，加入"必须完成"并调整时间线
4. 修改后通过 PR 提交，review 通过后方可合并
